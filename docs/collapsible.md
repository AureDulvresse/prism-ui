# Collapsible

`resources/views/components/halo/collapsible/{index,trigger,content}.blade.php`

## Props

`<x-halo::collapsible>`:

| Prop | Type | Default | Notes |
|---|---|---|---|
| `open` | `bool` | `false` | Whether the section starts expanded |

`collapsible.trigger`:

| Prop | Type | Default | Notes |
|---|---|---|---|
| `icon` | `bool` | `true` | Show the chevron icon that rotates with the open state |

`collapsible.content` takes no props beyond pass-through attributes.

## Examples

```blade
<x-halo::collapsible>
    <x-halo::collapsible.trigger>What is HaloUI?</x-halo::collapsible.trigger>
    <x-halo::collapsible.content>
        A Blade component library for Laravel.
    </x-halo::collapsible.content>
</x-halo::collapsible>

<x-halo::collapsible open>
    {{-- starts expanded --}}
    <x-halo::collapsible.trigger :icon="false">Details</x-halo::collapsible.trigger>
    <x-halo::collapsible.content>
        Expanded on first render.
    </x-halo::collapsible.content>
</x-halo::collapsible>
```

## Accessibility

The trigger button has `aria-expanded` reflecting the open state and `aria-controls` pointing at the content panel's `id`. The content panel has `role="region"` and `aria-labelledby` pointing back at the trigger's `id`. Both ids are generated by Alpine's `$id()` magic, scoped by the `x-id` declared on `collapsible/index.blade.php` — this is what lets the trigger and content stay linked without either sub-component needing to know about the other. The chevron icon rotates 180° when open (a visual cue only — `aria-expanded` carries the actual state).

## Implementation

Registered as `Alpine.data('haloCollapsible', ...)` in `resources/js/init.js`. It's the same open/close mechanic as one `accordion.item`, simplified to a single boolean (`open`) and a `toggle()` method — no group state, no `multiple` concept, since a Collapsible is always standalone.
